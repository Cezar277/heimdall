# T116 — preuves pour la ligne SAMM (Empreinte HMAC avec clé serveur)

Sous-ticket **T402** (ticket GitHub **#116**) du grand ticket `#40 « États du secret dans le Vault »`,
branche `116-t402-empreinte-hmac-avec-clé-serveur`. Cette fiche fournit les couples
**module + ligne** et les tests qui prouvent la checklist ; elle ne remplace pas la revue de code.

## 1. Exigences du ticket et preuves

> **Permaliens** : les liens ci-dessous sont épinglés au dernier commit de code
> [`a731a3d`](https://github.com/Cezar277/heimdall/commit/a731a3dd9100fb3f59af65a3ce081342f2958136).
> Les éventuels commits de documentation postérieurs ne modifient aucune ligne de code citée, donc les preuves
> restent valables au SHA de merge. À la fusion, re-pinner les permaliens sur le SHA de merge via
> `python scripts/repin_samm.py --sha <sha-merge> --fiche docs/t116-samm.md`.
> Cette révision intègre le calcul HMAC, la séparation des clés (formes encodées comprises), le contrôle canari et l'interdiction
> fail-closed de transition de mode (dérivé ↔ explicite sans migration), le contrôle de continuité HMAC immédiat
> en rotation de KEK (mémoire et SQLite sous transaction), **y compris sur un store ou une base vidée par `delete()`
> dès qu'un canari persiste (sans `clear()`)**, la propagation fail-closed des erreurs de précondition
> sur `verify_secret_hmac`, le support des octets bruts non-UTF8 sans appel à `decode("utf-8")` prévenant tout risque
> de `UnicodeDecodeError`, la réinitialisation du canari dans `clear()`, la validation stricte de type et la borne maximale
> (512 octets) sur la clé HMAC, l'isolation fail-closed post-rotation, le canari d'invalidation dérivé par HMAC,
> la protection canari et mode explicite sur `find_secrets_by_fingerprint`, la conversion d'erreur canari en `VaultCipherError`,
> la validation du triplet d'identité et rejet de l'AAD vide, le contrôle d'entropie de Shannon durci (au moins 24 symboles distincts, Shannon $\ge 4.0$),
> **la garde anti-phrase humaine (≥ 32 caractères normalisés à ≥ 85 % de minuscules ASCII/espaces) et la portée
> documentée de la garantie 256 bits — prouvée uniquement via `generate_server_hmac_key()` (CSPRNG), les seuils
> de la garde opérateur restant une défense heuristique non relevable davantage**, le contrôle **master vs HMAC**
> dans `from_master_key` (invariant 5, usage librairie directe),
> la parité NFC création / vérification (invariant 1), la parité NFC des candidats `bytes` UTF-8 (NFD/NFC) avec conservation
> des octets non-UTF8 bruts, le verrouillage de parité cipher / stores pour empreinte attendue malformée,
> la parité de valeur vide, la parité de repli déchiffrement pour lignes héritées, le refus fail-closed de la recherche
> par empreinte sur une base 100 % héritée sans canari, la suppression de l'extraction de clé et l'indexation SQLite.
> Cette fiche est le commit de documentation associé.
