## 4. STRIDE et invariants

| Menace / exigence | Traitement | Preuve |
|---|---|---|
| **Information disclosure** — KEK compromise & workers en mémoire | La rotation de la KEK réenveloppe toutes les DEK sans toucher aux valeurs chiffrées ; l'ancienne KEK ne peut plus déchiffrer aucune DEK. Les stores en mémoire détectent toute rotation externe sous `BEGIN IMMEDIATE` (`SqliteSecretStore.create` refuse fail-closed avec `RuntimeError` si la base a une version supérieure) évitant de créer de nouveaux secrets avec une KEK compromise. La rotation hors-ligne exige le redémarrage des workers. En cas de crash entre commit et swap mémoire, le redémarrage recharge automatiquement la version via `_detect_current_kek_version`. | `tests/test_vault_kek_rotation.py::DatabaseRotationTests::test_rotation_rewraps_only_deks_without_touching_values`, `::StoreRotationMethodTests::test_sqlite_store_create_rejects_stale_cipher_after_external_rotation`, `::StoreRotationMethodTests::test_sqlite_store_reinit_after_simulated_crash_reloads_version` |
| **Tampering** — rotation interrompue / corruption | Transaction SQLite exclusive (`BEGIN IMMEDIATE`) : toute erreur (décodage, clé invalide) entraîne un rollback immédiat, laissant la base dans son état cohérent initial. Aucun helper d'écriture ne commite la transaction de l'appelant (`_write_transaction` sous `SAVEPOINT`) : un échec ultérieur dans la même `db_session` annule l'intégralité des écritures, y compris plusieurs helpers chaînés (pas d'état partiel). La portée transactionnelle est portée par la connexion elle-même (`_SessionConnection._heimdall_session`, posé par `db_session`), sans registre global d'`id()` : deux sessions concurrentes ne peuvent pas se classer ni se commiter mutuellement. En mémoire, `InMemorySecretStore.rotate_kek` restaure `_secrets` **et le couple `(cipher, kek_version)`** sur `BaseException` (`KeyboardInterrupt`, `asyncio.CancelledError`) : une interruption entre les deux affectations de sortie ne laisse jamais un cipher neuf avec d'anciennes DEK. Côté SQLite, le swap `(cipher, kek_version)` est atomique avec restauration sur `BaseException` : une interruption entre les deux affectations ne laisse pas un cipher neuf étiqueté avec l'ancienne version, et un `create` ultérieur échoue fail-closed (`RuntimeError`) sur la version DB supérieure. Après un commit DB sans swap mémoire (fenêtre de crash), la relecture avec l'ancien cipher échoue fail-closed (`SecretStoreError` générique). | `tests/test_vault_kek_rotation.py::DatabaseRotationTests::test_rotation_atomicity_rolls_back_on_error`, `::NestedTransactionIsolationTests::test_two_helpers_chained_in_same_session_roll_back_together`, `::NestedTransactionIsolationTests::test_concurrent_sessions_do_not_cross_commit`, `::StoreRotationMethodTests::test_in_memory_rotate_kek_atomicity_on_base_exception`, `::StoreRotationMethodTests::test_in_memory_rotate_kek_restores_cipher_and_version_on_interrupt`, `::StoreRotationMethodTests::test_sqlite_store_rotate_kek_restores_cipher_and_version_on_interrupt`, `::StoreRotationMethodTests::test_sqlite_store_read_after_crash_window_fails_closed_with_stale_cipher`, `::VaultRotateCliTests::test_cli_rotate_two_concurrent_processes_one_fails_closed` |
| **Information disclosure** — rémanence mémoire de la DEK | La DEK déchiffrée en mémoire lors du réenveloppement est stockée dans un `bytearray` remis à zéro (`b"\x00" * 32`) dans un bloc `finally` (meilleur effort compte tenu des copies immuables CPython). | `heimdall/vault/crypto.py` (`rewrap_dek`), `tests/test_vault_kek_rotation.py` |
| **Denial of Service** — migration dégradée | `_ensure_secret_kek_version_column` est idempotente, concurrente et additive ; les bases pré-#71 conservent leurs données avec `kek_version=1`. | `tests/test_vault_kek_rotation.py::SchemaMigrationTests::test_schema_migration_adds_kek_version_without_data_loss` |
| **Invariant 5** — KEK distinctes | La commande CLI et la méthode de base refusent la rotation si l'ancienne et la nouvelle KEK sont identiques. | `tests/test_vault_kek_rotation.py::DatabaseRotationTests::test_rotation_rejects_identical_ciphers`, `::VaultRotateCliTests::test_cli_rotate_rejects_identical_keys` |
| **Invariant 8** — Pas de reflet de secret dans les erreurs | Messages génériques sur échec opérationnel (code 1) ou d'usage (code 2), aucune clé affichée dans stderr ni dans les exceptions de contention ; protection contre le reflet de `kek_version` corrompue dans SQLite, InMemory et reenvelope ; distinction stricte exit 1 (opérationnel / intégrité DB) vs exit 2 (usage / downgrade) en CLI sans reflet, par types dédiés `KekVersionError` / `KekConcurrencyError` héritant de `RuntimeError` (plus de confusion avec les erreurs d'usage `ValueError`, plus de matching sur le libellé français), y compris dans `InMemorySecretStore` ; les messages de version ne réfléchissent plus les numéros cible/courant. | `tests/test_vault_kek_rotation.py::VaultRotateCliTests::test_cli_rotate_wrong_old_key_exits_one`, `::VaultRotateCliTests::test_cli_rotate_corrupted_kek_version_exits_one`, `::VaultRotateCliTests::test_cli_rotate_concurrency_error_exits_one_without_reflection`, `::DatabaseRotationTests::test_rotation_under_lock_contention_fails_closed`, `::RotateSecretsKekCorruptedVersionTests`, `::SqliteStoreDetectKekVersionTests`, `::StoreRotationMethodTests::test_in_memory_rotate_kek_corrupted_version_raises_generic_error`, `::StoreRotationMethodTests::test_in_memory_rotate_kek_rejects_oversized_version_without_reflection` |
| **Invariant 9** — Pas de clé secrète dans argv | Options CLI supprimées (`--old-kek`, `--new-kek`, etc.) ; injection des KEK/passphrases uniquement via variables d'environnement (`HEIMDALL_VAULT_*`), interdisant l'exfiltration via `ps aux` ou `/proc` ; fail-closed si variable vide sans repli silencieux. | `tests/test_vault_kek_rotation.py::VaultRotateCliTests::test_cli_rotate_no_key_options_in_help_or_argv`, `::VaultRotateCliTests::test_cli_rotate_empty_old_kek_env_var_fails_closed_without_fallback` |
| **Intégrité & Monotonie** — Anti-downgrade `kek_version` | Validation systématique (`validate_kek_version` dans `[1, 2**63-1]`, borne des INTEGER signés 64 bits de SQLite) et refus strict d'une version cible inférieure ou égale à la version courante (`target_kek_version <= max(current)`) dans `rotate_secrets_kek` et `reenvelope_secret` (clause conditionnelle atomique et verrouillage `BEGIN IMMEDIATE`) ; refus explicite (`ValueError`) d'un downgrade explicite et `KekConcurrencyError` sur bump concurrent, y compris quand `kek_version` est omise (garde optimiste sur la version lue). L'auto-incrément (`validate_kek_version(current_max + 1)`) échoue `ValueError` au sommet de l'intervalle au lieu de persister un REAL, les trois gardes (`rotate_secrets_kek`, `_read_max_kek_version`, `InMemorySecretStore.rotate_kek`) rejettent aussi explicitement `> MAX_KEK_VERSION`, et l'écriture de rotation est conditionnelle (`UPDATE ... WHERE id = ? AND kek_version < ?` + `rowcount`) : impossible de rétrograder une ligne (`v3 -> v2`) ou d'en écraser une, y compris entre deux rotations concurrentes sérialisées par `BEGIN IMMEDIATE`. | `tests/test_vault_kek_rotation.py::DatabaseRotationTests::test_rotation_rejects_downgrade_or_same_version`, `::DatabaseRotationTests::test_rotation_refuses_auto_increment_beyond_sqlite_integer_max`, `::DatabaseRotationTests::test_rotate_secrets_kek_update_is_version_guarded_no_downgrade`, `::DatabaseRotationTests::test_concurrent_double_rotation_serializes_without_downgrade`, `::KekVersionValidationTests`, `::ReenvelopeSecretMonotonicityTests`, `::ValidateKekVersionHelperTests::test_validate_kek_version_bounds_sqlite_signed_integer`, `::VaultRotateCliTests::test_cli_rotate_rejects_target_version_above_sqlite_integer_range`, `::VaultRotateCliTests::test_cli_rotate_rejects_auto_increment_overflow_at_max`, `::SqliteStoreDetectKekVersionTests::test_detect_kek_version_oversized_real_raises_generic_error_no_reflection`, `::StoreRotationMethodTests::test_in_memory_rotate_kek_rejects_oversized_version_without_reflection`, `::VaultRotateCliTests::test_cli_rotate_two_concurrent_processes_one_fails_closed`, `::NestedTransactionIsolationTests::test_update_secret_without_kek_version_refuses_concurrent_rotation` |
| **Traçabilité post-rotation** — Nouveaux secrets | Suivi de la version courante (`_kek_version`) dans `SqliteSecretStore` et `InMemorySecretStore` : les secrets créés après rotation héritent de la nouvelle version KEK, alignée sur la `new_version` retournée par `rotate_secrets_kek` sans SELECT supplémentaire ni dérive future. | `tests/test_vault_kek_rotation.py::StoreRotationMethodTests::test_sqlite_store_create_after_rotate_has_target_kek_version`, `::test_in_memory_store_create_after_rotate_has_target_kek_version`, `::test_sqlite_store_rotate_kek_persists_returned_new_version_without_drift` |
| **Fail-closed opérationnel** — Base inexistante ou vide | La commande CLI refuse de créer silencieusement une base vide (code 2 si fichier absent/vide, code 1 si 0 secret) ; les stores retournent 0 sans changer de KEK si 0 secret ; `rotate_secrets_kek` retourne `(0, 1)` sur base vide sans altérer la base même avec `--target-version` (LOW 2) ; détection de version fail-closed. | `tests/test_vault_kek_rotation.py::VaultRotateCliTests::test_cli_rotate_missing_or_empty_database_fails_closed`, `::StoreRotationMethodTests::test_sqlite_store_rotate_empty_does_not_swap_cipher`, `::SqliteStoreDetectKekVersionTests`, `::DatabaseRotationTests::test_rotation_on_empty_db_with_target_version_returns_one_and_writes_nothing`, `::DatabaseRotationTests::test_rotation_refuses_auto_increment_beyond_sqlite_integer_max`, `::VaultRotateCliTests::test_cli_rotate_rejects_auto_increment_overflow_at_max` |
| **Confinement du chemin** — symlink refusé sans suivi | Le pré-contrôle CLI utilise `os.lstat` (jamais `stat`) et exige un fichier régulier non vide : un `--db-path` symlink est refusé en code 2 sans être suivi, avec un message générique sans chemin (invariant 8) ; la garde d'ouverture `O_NOFOLLOW` de `db_session` reste la seconde barrière. | `tests/test_vault_kek_rotation.py::VaultRotateCliTests::test_cli_rotate_rejects_symlink_db_path_without_following` |
| **Intégrité zéro-déchiffrement** — HMAC auxiliaire | L'empreinte HMAC auxiliaire n'est pas modifiée lors de la rotation pour préserver l'absence totale de déchiffrement des valeurs (DoD #71). | `heimdall/vault/crypto.py` (`fingerprint`), `heimdall/vault/database.py` (`rotate_secrets_kek`) |
