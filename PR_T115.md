## Ce qui a changé

- **Module `heimdall/vault/transitions.py`** :
  - Formalise le cycle de vie complet d'un secret : `detecte -> confirme -> vaulte -> rote`, avec gestion de l'état `faux_positif` (écarté).
  - Définit les constantes de référence : `SecretLifecycleState`, `LIFECYCLE_STATES`, `INITIAL_STATE = "detecte"`, `TERMINAL_STATES = frozenset({"rote"})`.
  - Définit la table des transitions autorisées `ALLOWED_TRANSITIONS` (5 transitions permises), 100 % cohérente avec le schéma et le diagramme d'états du ticket #14 (`docs/contracts/finding.md`).
  - Formalise la table exhaustive des 20 transitions interdites `FORBIDDEN_TRANSITION_REASONS` avec justifications fermées pour chaque interdiction (passages directs interdits comme `detecte -> rote` ou `detecte -> vaulte`, retours arrière interdits, interdiction d'entrer dans le Vault pour un faux positif, terminalité de `rote`).
  - Implémente `canonicalize_state` (avec gestion de l'alias métier `ecarte`), `is_transition_allowed`, `validate_transition` (fail-closed, lève `InvalidTransitionError` ou `UnknownStateError`), `get_allowed_transitions`, `get_forbidden_transitions` et `get_transition_matrix` (matrice 5x5 complète).
- **Architecture & Décision : `docs/adr/006-table-etats-et-transitions.md`** :
  - Formalise le cycle de vie du secret et la justification de la compromission irréversible d'un secret ayant fuité.
  - Décide formellement du sort du faux positif (état « écarté » / `faux_positif`) en lien avec #33 : rôle consultatif du LLM sans pouvoir de transition, justification fermée tracée dans `llm-rejections.jsonl`, validation humaine obligatoire (dialogue Y/N/E #32), interdiction absolue d'entrer dans le Vault, fail-closed en CI sans dispense automatique, réexamen explicite vers `detecte`.
- **Tests : `tests/test_vault_transitions.py`** :
  - 21 tests unitaires, 71 sous-cas couvrant 100 % des branches et instructions du module `heimdall.vault.transitions`.
  - Vérifie la conformité avec le contrat Finding #14.
  - Vérifie la chaîne nominale complète `detecte -> confirme -> vaulte -> rote`.
  - Vérifie exhaustivement les 20 transitions interdites (1 par 1) et leurs messages d'erreur statiques.
  - Vérifie les transitions réflexives, les alias (`ecarte`), la partition des états et la matrice complète 5x5.

Démonstration interactive des transitions autorisées et interdites :

```sh
.venv/bin/python - <<'PY'
from heimdall.vault.transitions import validate_transition, InvalidTransitionError

# 1. Chaîne nominale autorisée
validate_transition("detecte", "confirme")
validate_transition("confirme", "vaulte")
validate_transition("vaulte", "rote")
print("Chaîne nominale : OK")

# 2. Passage direct interdit
try:
    validate_transition("detecte", "rote")
except InvalidTransitionError as exc:
    print("Saut direct détecté -> roté :", exc)

# 3. Faux positif interdit dans le Vault
try:
    validate_transition("ecarte", "vaulte")
except InvalidTransitionError as exc:
    print("Faux positif vers Vault :", exc)
PY
```
